# CAPSERA — Shared API Contract (`API_CONTRACT.md`)

- **Status:** Baseline Conventions Established / Module Payloads Pending Team Specification
- **Source of Truth:** [CAPSERA PRD v1.0](./PRD.md) (Sections 10 & 11)
- **Base URL Prefix:** `/api/v1`

> **Important:** This file establishes only the canonical conventions, response envelopes, status codes, and endpoint map defined in PRD v1.0. Exact request bodies, query parameters, and response DTO fields for each module are labeled **UNRESOLVED** below and must be agreed upon by the owning member and team before implementation.

---

## 1. Global API Conventions (Established by PRD)

1. **Base Path:** All REST endpoints are mounted under `/api/v1`.
2. **Resource Naming:** Plural nouns in URL paths; consistent HTTP verbs (`GET`, `POST`, `PUT`, `PATCH`, `DELETE`).
3. **Content Type:** `application/json` for standard requests and responses.
4. **Field Naming:** All JSON request and response keys use `camelCase` (e.g., `traineeId`, `courseId`, `createdAt`).
   - Do not introduce synonyms for canonical fields (e.g., always use `traineeId`, never `studentId` or `learnerId`).
5. **Identifiers:** Primary keys are generated by the database (PostgreSQL per `ADR-002`) and are never trusted from public signup payloads for ownership or role assignment.
6. **Timestamps:** All timestamps returned in API responses must be ISO 8601 UTC strings (e.g., `"2026-11-03T09:00:00.000Z"`).
7. **Pagination:** List endpoints that may grow accept query parameters:
   - `page` (default: `1`, minimum: `1`)
   - `pageSize` (default: `20`, maximum: `100`)
8. **Authentication & Authorization:** All non-public endpoints enforce active authentication (`status === 'ACTIVE'`) and role/ownership checks on the server.

## 2. Canonical Response Envelopes (Established by PRD Section 11.2)

### 2.1 Single Resource / Action Success
```json
{
  "success": true,
  "data": {}
}
```

### 2.2 Paginated List Success
```json
{
  "success": true,
  "data": {
    "items": [],
    "pagination": {
      "page": 1,
      "pageSize": 20,
      "totalItems": 0,
      "totalPages": 0
    }
  }
}
```

### 2.3 Error Response
```json
{
  "success": false,
  "error": {
    "code": "VALIDATION_ERROR",
    "message": "A human-readable message"
  }
}
```

## 3. Canonical HTTP Status Codes (Established by PRD Section 11.3)

| Status Code | Meaning |
|---|---|
| `200 OK` | Successful read, update, or synchronous action |
| `201 Created` | Resource successfully created |
| `204 No Content` | Successful deletion/archive where no response body is needed |
| `400 Bad Request` | Validation error or malformed input |
| `401 Unauthorized` | Missing or invalid authentication |
| `403 Forbidden` | Authenticated, but role/ownership forbidden or account is not `ACTIVE` (`PENDING`, `REJECTED`, `SUSPENDED`) |
| `404 Not Found` | Target resource does not exist (or is hidden by visibility rules) |
| `409 Conflict` | Duplicate or conflicting state operation |
| `413 Payload Too Large` | Uploaded file exceeds permitted size limit |
| `415 Unsupported Media Type` | Uploaded file MIME/type is not permitted |
| `429 Too Many Requests` | Rate limit exceeded |
| `500 Internal Server Error` | Unexpected server error (never expose raw SQL errors or secrets) |

## 4. Canonical Enum Values (Established by PRD Section 10.3)

- **Roles:** `TRAINEE` | `TRAINER` | `ADMIN`
- **User Statuses:** `PENDING` | `ACTIVE` | `REJECTED` | `SUSPENDED`
- **Course Statuses:** `DRAFT` | `PUBLISHED` | `ARCHIVED`
- **Assessment Statuses:** `DRAFT` | `PUBLISHED` | `CLOSED`
- **Enrollment Statuses:** `ACTIVE` | `COMPLETED` | `CANCELLED`
- **Attempt Statuses:** `IN_PROGRESS` | `SUBMITTED` | `GRADED` | `EXPIRED`
- **Resource Types:** `VIDEO` | `PRESENTATION` | `DOCUMENT` | `LINK` | `OTHER`

## 5. Foundation Health Endpoint (Implemented)

### `GET /api/v1/health`
- **Access:** Public (used for local development and deployment readiness checks).
- **Query Params:** Optional `?db=true` to ping the PostgreSQL pool (`SELECT 1 AS ok`).
- **Response (`200 OK`):**
```json
{
  "success": true,
  "data": {
    "service": "capsera-api",
    "status": "OK",
    "timestamp": "2026-11-03T09:00:00.000Z",
    "database": {
      "checked": false,
      "engine": "postgresql",
      "status": "SKIPPED",
      "name": "capsera_db"
    }
  }
}
```
